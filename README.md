# home-assistant-sigur

[![CI](https://github.com/gOsToFf/home-assistant-sigur/actions/workflows/ci.yml/badge.svg)](https://github.com/gOsToFf/home-assistant-sigur/actions/workflows/ci.yml)
[![hacs](https://img.shields.io/badge/HACS-Custom-41BDF5.svg)](https://hacs.xyz/)

Неофициальная интеграция СКУД **Sigur** с **Home Assistant**, работающая напрямую
по протоколу **OIF** поверх TCP/TLS. Даёт состояния точек доступа, события
проходов в реальном времени и безопасное управление дверями. Устанавливается и
обновляется через HACS.

> **Интеграция неофициальная.** Она не аффилирована с компанией «Промавтоматика»
> и с торговой маркой «Sigur», не поддерживается ими и разработана независимо на
> основе публичной спецификации «Протокол интеграции OIF» (редакция от
> 27.01.2025, OIF 1.8, ПО Sigur 1.6.3.14).

## Возможности

- Несколько независимых серверов Sigur в одном Home Assistant — каждый своей
  записью конфигурации, со своими устройствами и сущностями.
- Автоматическое обнаружение зон и точек доступа (`GETZONEINFO`, `GETAPLIST`,
  `GETAPINFO`).
- Отдельное устройство Home Assistant на каждую точку доступа, привязанное к
  устройству-серверу.
- События в реальном времени через `SUBSCRIBE CE_WITH_NAMES` с автоматическим
  откатом на `CE` и на классический формат для старых версий Sigur.
- Публикация событий в шину Home Assistant (`sigur_event`) и device triggers для
  автоматизаций.
- Восстановление пропущенных событий через `GETHISTORY` после разрыва связи, с
  дедупликацией.
- Автоматическое переподключение с экспоненциальной задержкой и джиттером.
- Безопасное управление режимом точки доступа (`SETAPMODE`) и разрешение
  однократного прохода (`ALLOWPASS`) — **по умолчанию выключено**.
- TLS, проверка сертификата сервера, свой CA и взаимная аутентификация (mTLS).
- Диагностика с маскированием персональных данных и Repair-уведомления.
- Опциональный исходящий webhook с подписью HMAC-SHA256 — **по умолчанию
  выключен**.

## Требования

- Home Assistant **2025.12** или новее.
- ПО Sigur с включённым портом интеграций СКУД. TLS поддерживается начиная с
  версии Sigur **1.6.0.1**.

## Настройка на стороне Sigur

1. Откройте ПО **«Управление сервером»**, вкладка **«Порты»**.
2. Включите чек-бокс **«Порты интеграций СКУД»**. По умолчанию используется порт
   **TCP 3312**, его можно изменить.
3. Для шифрования включите **«Использовать TLS»** для порта открытого интерфейса
   СКУД. Предварительно настройте хранилище сертификатов сервера согласно
   разделу «Установка зашифрованного соединения между клиентом и сервером»
   «Руководства администратора ПО Sigur».
4. Сохраните настройки и **перезапустите серверный модуль**.
5. Создайте или выберите оператора СКУД (раздел «Операторы системы»
   «Руководства пользователя ПО Sigur») и убедитесь, что у него есть право
   **«Доступ по протоколу OIF (Интеграции)»**. Его логин и пароль вводятся при
   настройке интеграции.

> ⚠️ **В версии протокола OIF 1.8 пароль оператора передаётся внутри протокола
> открытым текстом.** Настоятельно рекомендуется включить TLS. Если TLS
> невозможен, используйте выделенного оператора с минимальными правами и
> изолированный сетевой сегмент.

Если на сервере включена **взаимная аутентификация**, интеграции нужно указать
клиентский сертификат и закрытый ключ; сертификат должен быть подписан
доверенным для сервера удостоверяющим центром.

## Установка

### Через HACS (рекомендуется)

1. HACS → **Интеграции** → меню (⋮) → **Пользовательские репозитории**.
2. Добавьте `https://github.com/gOsToFf/home-assistant-sigur`, категория
   **Integration**.
3. Найдите **Sigur (OIF)**, установите и **перезапустите Home Assistant**.

### Вручную

Скопируйте каталог `custom_components/sigur` в `config/custom_components/` и
перезапустите Home Assistant.

## Добавление системы

**Настройки → Устройства и службы → Добавить интеграцию → Sigur (OIF)**.

| Поле | Описание |
|---|---|
| Название системы | Отображаемое имя, например `Sigur - Офис` |
| Хост / IP | Адрес сервера Sigur |
| Порт | По умолчанию `3312` |
| Логин / пароль оператора | Учётная запись с правом «Доступ по протоколу OIF» |
| Версия OIF | По умолчанию `1.8` |
| Использовать TLS | Настоятельно рекомендуется |
| Проверять сертификат сервера | Отключение — опасная опция, см. предупреждение ниже |
| Свой CA-бандл | Путь к файлу, если сервер использует собственный УЦ |
| Клиентский сертификат / ключ | Только при включённой взаимной аутентификации |

При добавлении интеграция подключается, выполняет `LOGIN` и делает read-only
проверку `GETZONEINFO`. Различаются ошибки: недоступен сервер, неверные учётные
данные, нет права OIF, отказ в доступе, неверный сертификат, неподдерживаемая
версия протокола. Запись не создаётся, если проверка не прошла.

> ⚠️ Отключение проверки сертификата позволяет перехватить пароль OIF, который
> в версии 1.8 передаётся открытым текстом. Используйте только в доверенной
> сети и осознанно.

Один и тот же `хост:порт` нельзя добавить дважды; разные системы Sigur —
сколько угодно. Поддерживаются повторная аутентификация (reauth) и смена
адреса/TLS (reconfigure) без потери устройств и сущностей.

## Устройства и сущности

**Устройство-сервер** — одно на запись конфигурации: состояние соединения,
режим подписки, число точек доступа, время последнего события.

**Устройство точки доступа** — по одному на каждый `ap-id`:

| Сущность | Тип | По умолчанию | Описание |
|---|---|---|---|
| Связь | `binary_sensor` (`connectivity`) | вкл. | `on`, пока есть связь с точкой |
| Дверь | `binary_sensor` (`door`) | вкл. | Физическое открытие; недоступна при `UNKNOWN` |
| Режим | `select` | вкл. | `normal` / `locked` / `unlocked` |
| Последнее событие | `event` | вкл. | Категория и атрибуты последнего события |
| Последнее обновление | `sensor` | вкл. | Время последнего успешного `GETAPINFO` |
| Последняя ошибка | `sensor` | выкл. | Диагностика |
| Зона входа / выхода | `sensor` | выкл. | Названия зон из `GETZONEINFO` |
| Время / направление / тип последнего прохода | `sensor` | выкл. | Диагностика |
| ID / имя объекта последнего прохода | `sensor` | **выкл. и требует опции ПДн** | Персональные данные |

Трёхпозиционный режим точки доступа не сводится к двум состояниям `lock`, поэтому
канонической сущностью является `select`, а `lock`-сущность не создаётся.

Сущности с персональными данными создаются только при включённой опции
**«Показывать персональные данные»**.

## События и автоматизации

Каждое событие публикуется в шину как `sigur_event`:

```yaml
server_entry_id: 01J...        # запись конфигурации, к которой относится событие
server_name: "Sigur - Офис"
occurred_at: "2025-01-27T11:23:08+03:00"
event_code: 4                  # числовой код EVENT_CE, null для событий из истории
event_type: pass_registered
category: pass_registered
description: "Pass registered"
access_point_id: 3
access_point_name: "Главный вход"
object_id: 6                   # null, если ПДн выключены
object_name: null              # только при включённых ПДн
direction_code: 2
direction: in                  # in | out | unknown | none
key_masked: "W26 ***23"        # номер пропуска никогда не публикуется целиком
```

> **Ключевайте автоматизации на `category`, а не на `event_code`.** Запрос
> `GETHISTORY` отвечает только в классическом формате, без числового кода, поэтому
> у восстановленных из истории событий `event_code` равен `null`.

Полная таблица кодов `EVENT_CE` (0–93 и расширенные диапазоны ОПС `256+N`,
`512+N`, `768+N`, `1024+N`) перенесена в
[`custom_components/sigur/api/event_codes.py`](custom_components/sigur/api/event_codes.py).
Неизвестный новый код не ломает интеграцию: он публикуется с
`category: unknown` и сохранённым числовым значением.

### Device triggers

Для каждой точки доступа доступны триггеры по категориям: зарегистрирован
проход, доступ разрешён / запрещён, взлом, открытие / закрытие двери, начало /
окончание удержания двери, потеря / восстановление связи, смена режима,
неисправность замка, питание от сети / аккумулятора, вскрытие корпуса, пожарная
тревога, событие ОПС, неизвестное событие.

### Пример автоматизации

```yaml
automation:
  - alias: "Уведомить о взломе"
    triggers:
      - trigger: device
        domain: sigur
        device_id: !input access_point_device
        type: break_in
    actions:
      - action: notify.mobile_app
        data:
          message: >-
            Взлом: {{ trigger.event.data.access_point_name }}
            в {{ trigger.event.data.occurred_at }}
```

### Пересылка событий во внешние системы

Рекомендуемый путь — штатная автоматизация Home Assistant с `rest_command`,
MQTT или любой другой интеграцией. Встроенный исходящий webhook — опция для
случаев, когда нужен прямой подписанный поток; см. ниже.

## Управление

Все возможности записи **выключены по умолчанию**. Включите
**«Разрешить управление точками доступа»** в настройках интеграции.

### `sigur.set_access_point_mode`

```yaml
action: sigur.set_access_point_mode
target:
  entity_id: select.glavnyi_vkhod_mode
data:
  mode: locked        # normal | locked | unlocked
```

`SETAPMODE ALL` никогда не отправляется неявно: точки всегда перечисляются
явными идентификаторами. Параметр `confirm_all_access_points` требует, чтобы
вызов действительно адресовал все точки доступа сервера.

### `sigur.allow_pass`

```yaml
action: sigur.allow_pass
target:
  entity_id: select.glavnyi_vkhod_mode
data:
  direction: in       # in | out | unknown
  object_id: 10       # опционально; без него проход анонимный
```

### `sigur.refresh`

Принудительный опрос выбранных серверов.

## Настройки интеграции

**Опрос, управление и приватность**

- Интервал опроса `GETAPINFO` (по умолчанию 30 с, минимум 5 с). События
  обновляют сущности мгновенно, опрос — подстраховка.
- Разрешить управление точками доступа.
- Показывать персональные данные в сущностях и событиях.
- Запрашивать имена объектов доступа по необходимости (`GETOBJECTINFO OBJECTID`
  с TTL-кэшем). `GETOBJECTINFO ALL` не используется никогда.

**События и история**

- Публикуемые категории событий (пусто = все).
- Восстанавливать пропущенные события после переподключения.
- Максимальное окно восстановления, 1–24 часа.
- Восстанавливать историю и при первом запуске (по умолчанию выключено, чтобы
  новая установка не заполнила Recorder старыми событиями).
- Добавлять в события исходное сообщение протокола (только для диагностики,
  может содержать ПДн).

**Исходящий webhook** — см. ниже.

## Исходящий webhook (необязательно)

Выключен по умолчанию. При включении требуется HTTPS-адрес (исключение —
приватный адрес с явным подтверждением) и секрет подписи. Каждая доставка
несёт заголовки:

| Заголовок | Значение |
|---|---|
| `X-Sigur-Timestamp` | Unix-время отправки |
| `X-Sigur-Nonce` | 128-битный одноразовый идентификатор |
| `X-Sigur-Signature` | `HMAC-SHA256(secret, timestamp + "." + nonce + "." + body)` |

Приёмник должен проверять подпись, отвергать устаревшие метки времени и
запоминать nonce, чтобы отбрасывать повторы. Имя объекта не передаётся, если это
не включено отдельно; номер пропуска передаётся только в маскированном виде.
Очередь ограничена, при недоступности приёмника отбрасываются самые старые
события — чтение OIF при этом никогда не блокируется.

Входящий webhook не реализован намеренно: для управления используйте штатный
аутентифицированный API Home Assistant и действия интеграции.

## Диагностика и Repairs

Диагностика записи конфигурации показывает состояние обоих соединений, версию
OIF, режим TLS, режим подписки, число зон и точек доступа, счётчики
переподключений и ошибок протокола, размер очереди webhook.

Никогда не попадают в диагностику: пароль, логин, номера пропусков, ФИО,
закрытые ключи, секрет webhook и его URL. Хост маскируется частично.
Идентификаторы объектов появляются только при включённой опции ПДн.

Repair-уведомления создаются при: отсутствии права OIF у оператора, невалидном
сертификате, неподдерживаемой версии протокола и длительной недоступности
сервера.

## Что намеренно не реализовано

`SYNCDB3`, `FACE_SYNC`, `BS_SYNC`, `DEVCONF_*`, `IP_SETCONF`, `DELEGATION_*`,
`LPREVENT`, `EXTFACEDETECT` — опасные, длительные либо узкоспециализированные
команды. Протокольный слой расширяем (`OifConnection.execute_stream` уже
поддерживает многострочные ответы), но эти команды не выведены в UI.

`IP_DISCOVER` рассматривается как диагностическое действие второй очереди. Поиск
выполняется сервером Sigur широковещательно в пределах его подсети и неприменим
к контроллерам E510, E2 и E4.

## Разработка

Протокольный слой (`custom_components/sigur/api/`) не импортирует Home Assistant
и запускается где угодно. Ядро Home Assistant импортирует `fcntl` и на Windows
не работает, поэтому его половина тестов требует Linux.

```bash
# Всё сразу, в контейнере (работает и на Windows)
docker build -f scripts/Dockerfile.tests -t sigur-tests .
docker run --rm -v "${PWD}:/workspace" sigur-tests python -m pytest -q

# Или локально на Linux / WSL
bash scripts/setup-dev-wsl.sh
~/.venvs/sigur/bin/python -m pytest -q
```

Проверка на реальном сервере — только через отдельный opt-in скрипт, который по
умолчанию выполняет исключительно read-only команды:

```bash
python scripts/probe_real_server.py --host sigur.example.com --username asuUser
```

Архитектурные решения описаны в [docs/adr-001-architecture.md](docs/adr-001-architecture.md).

## English summary

Unofficial Home Assistant integration for the **Sigur** access control system,
speaking the **OIF** protocol directly over TCP/TLS. Not affiliated with Sigur
or "Промавтоматика".

**What it does.** Discovers zones and access points, creates one Home Assistant
device per access point, exposes link state, physical door position and the
three-position lock mode, streams real-time events onto the event bus as
`sigur_event` with device triggers, recovers events missed during an outage via
a bounded `GETHISTORY` backfill, reconnects automatically, and — only once you
opt in — lets you set the access point mode and authorise a single pass.

**Setup.** Enable the SKUD integration port (TCP 3312 by default) on the
**Ports** tab of the Sigur server management tool, restart the server module,
and give an operator the **"OIF protocol access (Integrations)"** right. Then
add the integration from the Home Assistant UI. Install through HACS as a custom
repository.

**Security.** OIF 1.8 sends the operator password in clear text inside the
protocol, so TLS is strongly recommended; server certificate verification, a
custom CA bundle and mutual TLS are all supported. Every write capability and
everything carrying personal data is **off by default**. Credential numbers are
masked (`W26 ***23`) and never published or logged in full.

**Multi-server.** Several Sigur systems can run side by side; identifiers are
scoped per config entry, so two servers may reuse the same access point numbers
without colliding.

**Note on automations.** Key on the `category` field rather than `event_code`:
`GETHISTORY` only answers in the classic format, so backfilled events carry no
numeric `EVENT_CE` code.
