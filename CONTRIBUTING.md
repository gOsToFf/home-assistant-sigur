# Разработка

Протокольный слой (`custom_components/sigur/api/`) не импортирует Home Assistant
и запускается где угодно. Ядро Home Assistant импортирует `fcntl` и на Windows
не работает, поэтому его половина тестов требует Linux.

```bash
# Всё сразу, в контейнере (работает и на Windows)
docker build -f scripts/Dockerfile.tests -t sigur-tests .
docker run --rm -v "${PWD}:/workspace" sigur-tests python -m pytest -q

# Или локально на Linux / WSL
bash scripts/setup-dev-wsl.sh
~/.venvs/sigur/bin/python -m pytest -q
```

Проверка на реальном сервере — только отдельным скриптом, который запускается
вручную и по умолчанию выполняет исключительно команды чтения:

```bash
python scripts/probe_real_server.py --host sigur.example.com --username asuUser
```

Архитектурные решения описаны в [docs/adr-001-architecture.md](docs/adr-001-architecture.md).

## Выпуск версий

HACS читает **релизы** GitHub, а не теги: одного тега недостаточно. Пока
релизов нет, HACS показывает версию как хэш последнего коммита.

Порядок выпуска:

1. В ветке поднять `version` в `custom_components/sigur/manifest.json` и
   добавить раздел в `CHANGELOG.md`.
2. Смержить PR, затем поставить тег `v<версия>` и запушить его.
3. Workflow `release.yml` соберёт релиз сам: сверит тег с `manifest.json`,
   возьмёт в тело релиза только раздел этой версии из `CHANGELOG.md` и
   определит, пререлиз это или нет. Если тег и манифест разошлись или в
   changelog нет раздела — релиз не выйдет.

**Бета-версии.** Версия вида `0.3.0b1` (стиль Home Assistant) или
`0.3.0-beta.1` (semver) автоматически помечается на GitHub как pre-release.
HACS показывает такие релизы только тем, кто у себя включил переключатель
**Pre-release** для этого репозитория — он выключен по умолчанию, поэтому
бета не приедет обычным пользователям.

Важная тонкость: HACS считает бетой только пререлиз **новее** последнего
стабильного релиза. Пререлиз, выпущенный раньше стабильного, не будет виден
никому.

Проверить, что получится, можно до тега:

```bash
python scripts/release_metadata.py v0.2.3
```
